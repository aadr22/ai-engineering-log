## Mon Sep 28: NumPy vectorization

### What I learned
- Python loops are slow because every element is a full Python object
  with type lookups and new objects per step; NumPy runs one compiled
  loop over raw contiguous memory (plus SIMD)
- `shape` matters: (3,), (1, 3) and (3, 1) behave differently
- `axis` = the dimension that disappears; `keepdims=True` keeps it as size 1
- Broadcasting: compare shapes from the right; dims match if equal or 1
- Boolean masks replace loop + if; `np.maximum(a, 0)` is ReLU
- Use `np.allclose`, not `==`, to compare float results

### What I built
- Vectorized sum of squares, column z-score, negative clipping,
  and pairwise distances with 3-D broadcasting
- Speedups: Ex1 __x, Ex2 __x, Ex3 __x

### What confused me
- Pandas `.std()` uses n−1 but NumPy `np.std` uses n (ddof)


## Tue Sep 29: Matmul, views, argmax, seeds
- Check: row-wise percentages with keepdims, solved from memory
- `*` = element-wise; `@` = dot products of rows × columns,
  (m, n) @ (n, p) → (m, p)
- Slices and reshape are usually views: changing them changes the original
- argmax/argsort return positions; fancy indexing turns them into values
- Use np.random.default_rng(seed) for reproducible experiments

- His lesson (P2·06): K controls over/underfitting; L2 suits same-scale
  pixels; cosine suits embeddings; k-NN is the core of vector search and RAG
- Loop k-NN with Counter vote (ties go to the closest label automatically):
  - k=1: 0.9861 (9.4s), exactly matches the vectorized 1-NN, so logic proven

- ~9s per run vs well under 1s vectorized: why vectorization matters
